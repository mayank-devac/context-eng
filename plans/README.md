## What happened

The cause was neither the new hook nor Remote Control. Three small things combined:

| Piece | What it is | What went wrong |
|---|---|---|
| Global MCP config | Tells Claude (and Codex) how to start your memory server: `npx -y context-eng mcp` | It runs in whatever folder your session is in |
| `npx` | A tool that runs a package by name | Inside `context_eng`, your own `package.json` is also named `context-eng`, so npx used **your repo** through an old cache folder from Sep 22: `~/.npm/_npx/6cb1911107eecccd` |
| That old cache link | Points the `context-eng` command at a file | It still points at `dist/cli.js` (the old entry). Your real entry is now `dist/cli-entry.js` |

**The chain:**
```
1. Claude starts a session in context_eng → runs `npx -y context-eng mcp`
2. npx runs:  sh -c 'context-eng' mcp
3. `context-eng` → the old link → dist/cli.js
4. dist/cli.js has no "#!" first line (the line that says "run me with node")
   → macOS refuses to run it → sh reads it as a SHELL SCRIPT instead
5. sh hits your help text, lines like:
     context-eng mcp [--project <path>]
     context-eng hook --harness claude|codex --mode manual|automatic
   and runs them as commands. "|" means "pipe", so it also starts `codex --mode manual`
6. Each `context-eng` line runs step 3 again → about 9 new copies per copy
```

This is a **fork bomb** (a process that keeps cloning itself until the computer runs out of process slots). That explains every symptom:
- The CPU stays at 100% after you quit: the copies run in `sh`, not in Claude, so closing Claude doesn't stop them.
- Reinstalling Claude didn't help: the bad link lives in the npm cache.
- It started "recently": you began running sessions inside the `context_eng` folder after the entry file was renamed on Sep 28.
- The mysterious `codex --mode manual` processes come from the `claude|codex --mode manual` text in your help message.

> *Summary: a stale npx link made the shell read a JavaScript file as a shell script, and your help text happened to contain commands that start that same file again.*

## How to stop it happening again

I wrote two plans in [plans/](plans/README.md). These are instructions for another agent to carry out; I didn't change any source code:

- **[001](plans/001-shebang-on-cli-module.md)** (small): add `#!/usr/bin/env node` as the first line of `src/cli.ts`. Then even a wrong link runs Node, which loads the file and exits quietly. It includes a test that every command file has that first line.
- **[002](plans/002-absolute-mcp-launch.md)** (medium): change `context-eng init` to write the absolute `node` + `cli-entry.js` paths into MCP configs, the way your hook installer already does. `npx` stays only as a fallback, with a warning. The configs I fixed by hand today already look like this.

Do both: 001 makes a bad link harmless, and 002 stops npx from choosing your repo in the first place.
